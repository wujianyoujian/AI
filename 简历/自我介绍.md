#### 出现白屏如何查看
白屏的排查是分秒级的事情——先恢复，再复盘。核心逻辑：控制台 → 监控 → DOM →   兜底 → 回归。
  一、应急排查

  1. 控制台可打开时

  - 看 Console 红色报错——大多数白屏是 JS 运行时异常导致框架初始化中断
  - Network 面板确认 JS/CSS 是否返回 200，有没有 CDN 节点挂掉导致的资源 404
  - Elements 面板看 DOM 树是否为空——有节点说明渲染到了但可能样式问题隐藏了
  ，空节点说明框架根本没跑起来

  2. 控制台不可用时（线上用户侧）

  - 看监控平台的错误日志，过滤 JS 运行时异常和资源加载失败
  - 看自定义白屏埋点是否触发（如关键 DOM 缺失 + 持续无 DOM 变化 →
  判定白屏）
  - 按用户 ID / 设备 / 地域下钻，锁定影响面

  二、常见根因

  ┌─────────────────┬─────────────────────────────┬────────────────────┐
  │      原因       │            表现             │      排查方式      │
  ├─────────────────┼─────────────────────────────┼────────────────────┤
  │ JS 执行报错     │ 控制台红色报错，框架中断    │ onerror 日志 /     │
  │                 │                             │ 监控大盘           │
  ├─────────────────┼─────────────────────────────┼────────────────────┤
  │ 资源 404 / CDN  │ JS/CSS 加载失败             │ Network 面板 /     │
  │ 异常            │                             │ 资源加载监控       │
  ├─────────────────┼─────────────────────────────┼────────────────────┤
  │ 服务端异常      │ HTML 返回空 body            │ Network 看响应内容 │
  ├─────────────────┼─────────────────────────────┼────────────────────┤
  │ 渲染逻辑错误    │ DOM 树为空或根节点          │ Elements +         │
  │                 │ display:none                │ Computed 面板      │
  └─────────────────┴─────────────────────────────┴────────────────────┘
  三、兜底方案

  出了问题至少要"看不到白"，让用户知道系统在恢复：

  - 骨架屏：首屏兜底，即使 JS 挂了也有视觉反馈
  - React ErrorBoundary：组件级容错，局部报错不整页白
  - HTML 注入降级页：服务端层面最坏情况兜底，在 <body>
  插入"系统异常，请稍后重试"
  - 容器侧兜底页

  ---
  四、回归验证

  修复后进行回归验证，确保问题真正解决：

  - 复现环境回归（同设备 + 同网络 + 同操作路径）
  - 监控平台确认白屏埋点标记位恢复
  - 验证兜底方案可正常触发

#### fiber 架构，可中断
fiber 是啥，是一个结构，也是一个最小工作单元，从根fiber开始, 比如 App 函数组件 就是调用createElement从 tsx 转成 ，
就是 element，其实也是一个对象，主要 包含 props参数，children内容，属性
刚开始是一个根fiber children[0] => element, beginWork, 协调这个 element，也就是进行diff，构建出子 fiber出来，将 子fiber上 return => 父fiber，sibling => 相邻兄弟第一个fiber，父fiber 的child 指向 当前子fiber
子fiber 创建完成之后返回，深度优先，先child，后sibling，=> nextUnitOfWork

可中断是：每次执行完一个fiber 之后，看当前时间 是否大于于 5ms， 后续使用MessageChannel。postmessage 通知，nextUnitOfWork 当前fiber 继续执行，

React Fiber 完整工作流程

  一、Element（设计蓝图）                                                  
  JSX 经过 Babel 编译，调用 createElement，生成一个轻量对象：              
  // <App name="react" />
  {
    type: App,              // 组件函数
    props: { name: 'react' },
    key: null,
    ref: null,
  }

  它只描述"界面应该长什么样"，每次 render 都重新创建，用完就扔。

  二、Fiber（工作单元 + 数据结构）

  Fiber 也是一个对象，但比 Element 重得多，跨渲染复用：

  {
    tag: FunctionComponent,  // 类型标签
    type: App,               // 对应组件函数
    stateNode: null,         // 函数组件为 null，host 组件指向 DOM

    // 链表指针（核心）
    child: null,             // → 第一个子 Fiber
    sibling: null,           // → 下一个兄弟 Fiber
    return: null,            // → 父 Fiber

    // 双缓冲
    alternate: null,         // → 另一棵树中对应的 Fiber

    // 状态
    memoizedState: null,     // hooks 链表
    pendingProps: null,      // 即将应用的 props
    memoizedProps: null,     // 上一次的 props

    // 副作用
    flags: NoFlags,          // 增/删/改标记
    deletions: null,         // 待删除的子节点

    // 优先级
    lanes: NoLanes,
    childLanes: NoLanes,
  }

  Fiber 有两个身份：数据结构（持有状态、关联 DOM）和
  最小工作单元（每次处理一个 Fiber 节点）。

  三、从根 Fiber 开始

  整个 Fiber 树有一个手动创建的树根：

  // createFiberRoot 中，React 直接调用 createFiber(HostRoot, null, null,
  mode)
  // 不依赖任何 Element，手动组装出来的
  HostRoot Fiber = {
    tag: HostRoot,          // 3
    stateNode: FiberRootNode, // 指向管理容器
    child: null,
    // ...
  }

  调用 root.render(<App />) 后，<App /> 对应的 Element 被包成 update 塞进
  HostRoot 的 updateQueue。

  四、beginWork — 协调（Diff），构建子 Fiber 树

  从 HostRoot 开始，深度优先遍历：

  beginWork(HostRoot Fiber) {
    // 从 updateQueue 中取出 Element = <App name="react" />
    // 调和（diff）：拿新 Element 和旧 Fiber.alternate 比较
    // → 复用 / 新建 / 标记删除

    // 创建 App 的 Fiber，建立关系：
    HostRoot.child   = App Fiber       // 父 → 子
    App Fiber.return = HostRoot        // 子 → 父
  }

  beginWork(App Fiber) {
    // 执行 App() → 返回新的 Element 们：
    // <Header /> <Main><Sidebar /><Content /></Main> <Footer />

    // 调和子节点，构建 Fiber 链表：
    //                     sibling      sibling
    // App.child → Header ──────→ Main ──────→ Footer
    //               ↑ return      ↑ return      ↑ return
    //               └── App ──────┘              │
    //                                             │
    //           Main.child → Sidebar ──sibling──→ Content
    //                          ↑ return           ↑ return
    //                          └── Main ──────────┘
  }

  每次 beginWork 完成后，返回 nextUnitOfWork：先 child，没有 child 就
  sibling，都没有就向上找 return 的 sibling（completeWork 阶段）。

  五、可中断 — 时间切片

  function workLoopConcurrent() {
    // nextUnitOfWork 是全局变量，指向"下一个要处理的 Fiber"
    while (nextUnitOfWork !== null) {
      // 每处理完一个 Fiber，检查时间
      if (shouldYieldToHost()) {
        // 5ms 用完了 → 暂停！nextUnitOfWork 保留着，指向当前没干完的 Fiber
        break;
      }
      nextUnitOfWork = performUnitOfWork(nextUnitOfWork);
    }
  }

  shouldYieldToHost() 就是检查当前时间 ≥ deadline（startTime + 5ms），超过
  5ms 就让出主线程。

  六、恢复 — MessageChannel

  // packages/scheduler/src/forks/SchedulerHostConfig.default.js

  const channel = new MessageChannel();
  channel.port1.onmessage = performWorkUntilDeadline;

  // 暂停后，React 给自己发一条消息：
  port.postMessage(null);
  //    ↓ 浏览器在下一个宏任务执行
  //    ↓
  // channel.port1.onmessage 触发 → performWorkUntilDeadline
  //    ↓
  // 继续执行 workLoopConcurrent()
  //    ↓ nextUnitOfWork 还指着上次停下的地方
  //    ↓ 从它继续 beginWork

  七、完整链路图

  JSX
   ↓ Babel 编译
  createElement() → Element（轻量对象）
   ↓
  root.render(<App />) → Element 包成 update → 塞进 HostRoot.updateQueue
   ↓
  Scheduler 调度 → port.postMessage(null)
   ↓ 下一个宏任务
  performWorkUntilDeadline()
   ↓ deadline = now + 5ms
  workLoopConcurrent() {
    while (nextUnitOfWork) {
      if (shouldYieldToHost()) break;   ← 5ms 到了，暂停
      nextUnitOfWork = performUnitOfWork(fiber)
    }
  }
   ↓ 还有活？
  port.postMessage(null) ← 通知自己"继续干"
   ↓
  ... 循环直到 nextUnitOfWork === null
   ↓
  commitRoot() → 一次性把 Fiber 树的改动应用到 DOM

#### 事件合成

react 自己实现的一套事件系统，比如 onClick, 等事件都不是浏览器原生事件，对原来的事件进行了封装

- 跨浏览器兼容，不同浏览器的事件API有兼容性问题
- 事件委托，统一绑定在根节点上
- 批处理基础
- 跨平台：同一套事件抽象，React Native 也能用

1. 初始化，把所有的事件注册到root上，如 root.addEventListener("click", dispatchEvent);
2. 组件执行，渲染的时候，<div onClick={handleClick}></div> handleClick 存在当前组件对应的 fiber 节点上 也会指向dom 的 \_reactFiber，\_reactFiber.pendingProps.onClick 就是这个handleClick
3. 用户点击的时候，还是使用的原生 click，冒泡到 root 上，执行 dispatchEvent 方法
4. 找到 点击目标 target，获取到了fiber \_\_reactFiber
5. 通过当前节点中 return 指向父节点，向上获取到所有的 onClick方法，存放起来，就是所有冒泡的事件，然后执行，捕获同理
