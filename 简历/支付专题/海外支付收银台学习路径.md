# 海外支付收银台学习路径（Stripe + PayPal + Vue）

> 目标：能跑通两个官方收银台 demo，能讲清「内嵌 iframe 收卡 vs 跳转」两种架构，能把 3DS / 状态机 / 轮询讲出深度。
> 关联：[[支付前端面试专题]]

---

## 一、学完能讲清什么（验收标准）

1. 画出 Stripe 和 PayPal 两条完整收银台链路，说出前端在每个节点做什么
2. 讲清「内嵌收卡（Stripe Payment Element）」和「跳转（PayPal）」的本质区别，以及各自为什么这么设计
3. 讲清 3DS 2.0 的 frictionless / challenge 两种结果，前端怎么接
4. 讲清支付状态机、轮询兜底、异步通知三者的关系
5. 能说出「卡信息为什么不能落自己服务器」（PCI）

---

## 二、学习路径总览

```
阶段 0  建立心智模型（0.5 天，不写代码）
   ↓
阶段 1  跑通两个官方 demo（1~2 天）
   ↓
阶段 2  读懂收银台架构：内嵌 vs 跳转（1 天）
   ↓
阶段 3  深入 3DS / 状态机 / 轮询（2 天）
   ↓
阶段 4  自己模拟实现（2~3 天，面试深度来源）
```

核心逻辑：**先跑起来（有体感）→ 再读架构（有判断）→ 再深入细节（有深度）→ 最后自己实现（能讲透）**。

## 三、阶段任务

### 阶段 0：建立心智模型（0.5 天）

**任务**：不写代码，先把两张「链路图」看懂、能默画。

**Stripe 收银台链路**：
```
用户选商品 → 前端拿 clientSecret（后端创建 PaymentIntent）
   ↓
Payment Element 内嵌 iframe 收卡（卡号不进你服务器）
   ↓
confirmPayment → 后端调用 Stripe → 可能触发 3DS 挑战（内嵌弹窗）
   ↓
拿到结果 → 前端展示 → webhook 异步通知后端 → 前端刷新订单
```

**PayPal 收银台链路**：
```
用户点 Pay 按钮 → Smart Payment Buttons 弹窗/跳转 PayPal
   ↓
用户在 PayPal 侧登录、确认支付（前端全程不碰钱）
   ↓
onApprove 回调 → 前端拿 capture 结果 → 后端 verify 查单
   ↓
webhook 异步通知后端 → 前端刷新订单
```

**产出**：能默画这两张图，并能一句话说区别——「Stripe 把卡收在你这（iframe 隔离），PayPal 把人引到它那」。

---

### 阶段 1：跑通两个官方 demo（1~2 天）

**任务**：把两个 demo 都跑起来，用测试卡真实走一遍支付。

#### PayPal（先跑这个，跳转型最简单）

1. 注册 [developer.paypal.com](https://developer.paypal.com)，进 Dashboard 建 **沙箱 app**，拿 sandbox `client_id`
2. 跟着官方文档 [PayPal payments with single-page applications](https://developer.paypal.com/v5/checkout/single-page-app) 的 **Vue** 章节做（这是 PayPal 官方 Vue 接入的权威来源，比任何 GitHub demo 都新）
3. 核心就一件事：`@paypal/paypal-js` 的 `loadScript()` 加载 SDK → `paypal.Buttons({ createOrder, onApprove }).render('#container')` 渲染按钮，全程框架无关
4. 官方 GitHub 上**没有独立 Vue 示例仓库**，可参考 [paypal-examples/react-integration](https://github.com/paypal-examples/react-integration) 里 `@paypal/paypal-js` 的用法，自己包一层 Vue 组件
5. 点按钮 → 用**沙箱 buyer 账号**登录 → 完成支付 → 看 `onApprove` 触发

**关键观察点**：按钮点击后发生了「弹窗 → 跳 PayPal → 回来」，前端代码里没有任何「金额/卡号」，只有 `createOrder` / `onApprove` 两个回调。

#### Stripe（内嵌收卡，重点）

1. 注册 [dashboard.stripe.com](https://dashboard.stripe.com)，拿 `pk_test_` 和 `sk_test_`
2. 官方 demo 两种走法：
   - 直接打开 [vuestripe.com playground](https://vuestripe.com) 玩（最快，不用配环境）
   - 或 clone [vue-stripe/vue-stripe](https://github.com/vue-stripe/vue-stripe) 跑本地
3. 用测试卡 `4242 4242 4242 4242` 走一遍，再用 `4000 0000 0000 3220` 触发 3DS 挑战，**看弹窗长什么样**

**关键观察点**：卡号输入框是**嵌套 iframe**（右键看元素能发现是 Stripe 的域名），你的页面 JS 根本读不到卡号；3DS 挑战也是内嵌弹窗，全程不离开你的站。

**产出**：两个 demo 都能跑通 + 截图留档（面试可以直接说「我跑过 Stripe 沙箱，用 3220 卡触发过 3DS challenge」）。

---

### 阶段 2：读懂架构：内嵌 vs 跳转（1 天）

**任务**：回答一个核心问题——**为什么 Stripe 用内嵌 iframe，PayPal 用跳转？**

| 维度 | Stripe（内嵌） | PayPal（跳转） |
|---|---|---|
| 支付标的 | 卡 + 40+ 本地方式 | PayPal 账户（余额/绑卡） |
| 卡信息归属 | 必须 PCI 合规 → iframe 隔离 | 不需要你碰 → 用户去 PayPal 侧 |
| UX | 不离开收银台，转化率高 | 离开收银台，有流失风险 |
| 前端复杂度 | 高（iframe 通信、3DS 内嵌） | 低（两个回调搞定） |
| 风险 | 卡信息泄露风险，靠 iframe 隔离 | 跳转回跳校验、防钓鱼 |

**要能讲清的点**：
1. **iframe 隔离是 PCI 合规的解法**：卡号/CVV 只进网关的 iframe，你的 JS 拿不到，所以你的服务器不用过 PCI DSS 认证（等级降到 SAQ-A）
2. **内嵌为什么转化率高**：用户不离开收银台，减少跳转流失——这正是 JD 里「提升支付成功率」的关键手段之一
3. **跳转的风险**：`return_url` 回跳后**不能只看 URL 参数就认为成功**，必须再调后端查单

**产出**：能用这张表 + 三点理由，脱稿讲 3 分钟。

---

### 阶段 3：深入 3DS / 状态机 / 轮询（2 天）

**任务**：把三个「深度考点」逐个吃透（代码已在 [[支付前端面试专题]] 里）。

1. **3DS 2.0**：用 Stripe 的 `4000 0000 0000 3220`（必挑战）和 `4000 0000 0000 0446`（frictionless）两张卡，分别走一遍，**亲眼看两种结果的区别**。然后讲清：
   - frictionless = 风控判定低风险直接放行，用户无感
   - challenge = 高风险弹验证（OTP/生物识别）
   - 前端两种形态：`redirect`（整页跳）vs `iframe`（内嵌），iframe 用 `postMessage` 感知完成 + 超时兜底
2. **状态机**：把 `支付前端面试专题` 里的 `PayStateMachine` 自己抄一遍跑起来，理解「转移表 + onEnter/onExit」为什么能取代散落的 if/else
3. **轮询**：把 `usePayPolling` 抄一遍，重点体会**退避策略**和**终态才停**，再讲「为什么后端有 webhook 了前端还要轮询」

**产出**：三个考点都能脱稿讲 2 分钟，且每个都「亲手跑过/写过」。

---

### 阶段 4：自己模拟实现（2~3 天，面试深度来源）

**任务**：不接真实网关，自己写一个「模拟收银台 + 3DS 流程」的 Vue demo。这是把你和其他候选人的差距拉开的一步——**跑 demo 人人都会，自己实现一遍才说明真懂了**。

**要实现的东西**：
1. 收银台页：支付方式列表（配置驱动渲染）+ 金额展示（Intl 格式化多币种）
2. 模拟「后端返回 challenge」：用 `redirect` 和 `iframe` 两种形态
3. `iframe` 里用 `postMessage` 发「认证完成」消息，父页面监听 + 校验来源
4. 状态机驱动 UI + 结果轮询（退避）+ 超时兜底
5. 防重复提交 + 幂等键

**产出**：一个可运行的 Vue 3 项目（放在 `支付专题/demo/` 下），面试时「这个 3DS 流程我自己模拟实现过」是硬通货。
