## IOT设备运营平台
  1. Formily 低代码表单引擎

  真正的难点在哪：
  - Schema 如何设计才能同时满足"通用性"和"业务定制化"，这是低代码最核心的矛盾
  - 复杂联动逻辑（A字段变化 → B字段显隐/校验变化），Formily 的响应式依赖追踪你是怎么处理的
  - 跨业务模块的组件复用，版本升级时如何保证向后兼容、不影响存量配置
  - 非技术人员（产品/运营）配置表单时的容错设计

  亮点：
  - Schema 驱动 + 运行时渲染，彻底解耦 UI 与逻辑
  - 20+ 组件沉淀形成内部物料体系，这是有资产价值的

  ---
  2. RBAC 权限模块

  真正的难点在哪：
  - 多角色叠加时的权限冲突如何处理（取并集还是交集，边界情况怎么定义）
  - 前端路由权限 vs 按钮权限，与后端接口权限如何保持一致，避免前端绕过
  - 权限数据的缓存策略：每次路由切换都请求太重，不请求又可能权限过期
  - 动态路由生成（根据权限动态 addRoute）的时序问题，页面刷新时的白屏问题

  亮点：
  - 这个模块相对基础，亮点在于你是否做了动态权限热更新或多租户隔离，否则难以突出

  ---
  3. AntV X6 策略编排模块

  这是技术含量最高的一条，重点挖：

  真正的难点在哪：
  - 图编辑器的自定义节点渲染（React 组件嵌入 X6 Canvas）性能问题，节点多时如何优化
  - DAG 有向无环图的合法性校验（循环依赖检测），用户连线时实时拦截非法操作
  - 策略执行状态的实时同步：后端任务运行中，前端节点状态如何实时反映（轮询？WebSocket？）
  - 策略配置的序列化/反序列化，图数据结构如何持久化并保证还原一致性

  亮点：
  - 可视化 DAG 编排替代人工配置，这在 IoT 运营场景里本身是一个工程创新点
  - 如果你做了节点级别的执行状态实时回显，这个技术点非常值得写

  ---
  4. AI Agent 智能接入

  最有差异化，但也最难写好：

  真正的难点在哪：
  - 流式输出（SSE/Stream）的前端处理，如何做到打字机效果的同时保证异常容错
  - 多轮对话的上下文状态管理，会话隔离与历史记录的存储设计
  - 自动化流程的节点编排：如何定义 Agent 的触发条件、执行步骤、失败回滚
  - 大模型响应不稳定（超时、幻觉输出）时的降级策略

  亮点：
  - 将 AI 能力嵌入运营工作流，不是简单的对话框接入，而是流程自动化
  - 如果你做了 Prompt 工程（针对设备运营场景的定制化提示词）或 RAG 知识库接入，这是核心亮点
