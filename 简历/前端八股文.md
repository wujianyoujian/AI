# 一、JavaScript 核心

## 1. 数据类型与类型判断

**八种基本类型**：`undefined`、`null`、`boolean`、`number`、`string`、`bigint`、`symbol`、`object`（引用类型）。

null, undefined, boolean, number, string, object, bigint, symbol
**判断方法对比：**

| 方法 | 能判断 | 坑 |
|---|---|---|
| `typeof` | 基本类型 | `typeof null === 'object'`（历史 bug）；`typeof function === 'function'` |
| `instanceof` | 引用类型（原型链） | 不能跨 iframe；基本类型判断不了；可被 `Symbol.hasInstance` 篡改 |
| `Object.prototype.toString.call(x)` | 万能 | 返回 `[object Xxx]`，最可靠 |

**追问：为什么 `typeof null === 'object'`？** 历史原因——JS 早期用类型标签区分值，`null` 的机器码低位全为 0，和对象标签相同，遗留至今。

## 2. 隐式类型转换

**转换规则**：`ToPrimitive`（对象转原始值，先 valueOf 再 toString）、`==` 会触发类型转换、`+` 特殊（字符串优先）。

**经典题：**
```js
[] == ![]            // true
// 过程：![] → false（[] 是 truthy）；[] == false → []转"" → ""==false → 0==0 → true

1 + '2' === '12'     // + 遇到字符串转拼接
'5' - 3 === 2        // - 转数字
null >= 0            // true（>= 走数字比较，null → 0）
undefined == null    // true（特殊规定，只有这俩相等）
```

**追问：`==` 和 `===` 区别？** `===` 不转换类型，类型不同直接 false。**建议一律用 `===`**，`==` 的转换规则太隐晦容易出 bug。

## 3. 闭包

**定义**：函数 + 对其词法作用域的引用。即使外层函数执行完毕，内层函数仍能访问外层变量。

```js
function outer() {
  let count = 0
  return function () { return ++count }
}
const fn = outer()
fn() // 1 —— count 不会被 GC，因为闭包引用着它
```

**作用**：私有变量、模块化（IIFE / 模块模式）、柯里化、防抖节流、缓存。

**坑**：内存泄漏（闭包持有的变量不释放）、经典 for 循环 `var` 输出问题（`let` 或 IIFE 解决）。

**追问：闭包为什么会导致内存泄漏？** 闭包引用着作用域链上的变量，这些变量在闭包销毁前不会被垃圾回收；如果闭包被长期持有（如挂在全局、事件监听没解绑），内存就一直占用。

## 4. 作用域与原型链

**作用域链**：变量查找按「当前作用域 → 上级作用域 → ... → 全局」逐级向上，是**定义时**（词法）决定的，不是调用时。

**原型链**：`对象.__proto__` → 构造函数的 `prototype` → ... → `Object.prototype` → `null`。属性查找沿原型链向上。

```js
function Person(name) { this.name = name }
Person.prototype.say = function () { console.log(this.name) }
const p = new Person('鹏伟')
p.say() // 先在自身找 say，找不到沿 p.__proto__ (Person.prototype) 找
```

**一句话**：作用域链解决「变量在哪里找」，原型链解决「属性/方法在哪里找」。

**经典题**：`p.__proto__ === Person.prototype`，`Person.prototype.__proto__ === Object.prototype`，`Function.__proto__ === Function.prototype`。

## 5. this 指向

**判定规则（优先级从高到低）：**
1. `new` 调用 → this 指向新对象
2. `call` / `apply` / `bind` 显式绑定 → this 指向指定对象
3. 对象方法调用 `obj.fn()` → this 指向 `obj`
4. 普通函数调用 → 非严格模式指向 `window`，严格模式 `undefined`
5. **箭头函数没有自己的 this**，继承外层词法作用域的 this

**经典坑**：`const fn = obj.method; fn()` 会丢失 this（变为 window/undefined）；回调里 `this` 丢失；定时器里 this 指向 window。

**追问：bind 和 call 区别？** call/apply 立即执行，bind 返回一个绑定好 this 的新函数（可柯里化，`bind(obj, a, b)`）。apply 传数组，call 传参数列表。

## 6. 事件循环（Event Loop）

- JS 单线程，靠事件循环做异步。
- **宏任务**：整体 script、setTimeout/setInterval、I/O、UI 渲染、`postMessage`、`setImmediate`(Node)。
- **微任务**：`Promise.then/catch/finally`、`MutationObserver`、`queueMicrotask`、`process.nextTick`(Node，比微任务更早)。
- **顺序**：执行一个宏任务 → 清空**所有**微任务 → 判断是否需要渲染 → 下一个宏任务。
- **关键点**：微任务在当前宏任务结束后、渲染前全部执行完；每轮循环只会取一个宏任务。

```js
console.log(1)
setTimeout(() => console.log(2), 0)
new Promise(r => { console.log(3); r() }).then(() => console.log(4))
console.log(5)
// 1 3 5 4 2
// 解释：同步代码 1、3(Promise 构造器内同步执行)、5；微任务 4；宏任务 2
```

**追问：async/await 和事件循环的关系？** `await` 后面的代码等价于 `.then()` 回调，是微任务。`async` 函数返回 Promise。

## 7. Promise 与手写

**三种状态**：`pending` → `fulfilled` / `rejected`，不可逆。

| API | 行为 |
|---|---|
| `Promise.all` | 全成功才成功；一个 reject 立刻 reject（但其他仍会执行完） |
| `Promise.allSettled` | 等全部完成，返回 `{status, value/reason}` 数组，永不 reject |
| `Promise.race` | 最先 settled 的那个（无论成败） |
| `Promise.any` | 第一个成功的；全失败才 reject（AggregateError） |

**追问：Promise.all 里有一个 reject 会怎样？** 整体立即 reject，返回第一个 reject 的原因；但**其他 Promise 不会被取消**，仍继续执行（只是结果被忽略）。

## 8. 深浅拷贝

- **浅拷贝**：只复制第一层。`Object.assign`、扩展运算符 `{...obj}`、`Array.prototype.slice`、`concat`。
- **深拷贝**：递归复制所有层级。

```js
// 手写深拷贝（处理循环引用 + 常见类型）
function deepClone(obj, map = new WeakMap()) {
  if (obj === null || typeof obj !== 'object') return obj
  if (obj instanceof Date) return new Date(obj)
  if (obj instanceof RegExp) return new RegExp(obj)
  if (map.has(obj)) return map.get(obj) // 循环引用
  const clone = Array.isArray(obj) ? [] : {}
  map.set(obj, clone)
  for (const key in obj) {
    if (Object.prototype.hasOwnProperty.call(obj, key)) {
      clone[key] = deepClone(obj[key], map)
    }
  }
  return clone
}
```

**面试要点**：为什么用 `WeakMap` 存映射？——key 是弱引用，不会阻止原对象被 GC，且能解决循环引用导致的死循环。

**追问：structuredClone？** 原生深拷贝 API，支持循环引用、Date、Map/Set，但不能拷贝函数、Symbol、DOM 节点。

## 9. 防抖与节流

- **防抖（debounce）**：n 秒内重复触发只执行最后一次。场景：搜索框输入、resize、按钮防连点。
- **节流（throttle）**：n 秒内只执行一次。场景：滚动、拖拽、高频点击。

```js
// 防抖
function debounce(fn, delay) {
  let timer = null
  return function (...args) {
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), delay)
  }
}
// 节流
function throttle(fn, delay) {
  let last = 0
  return function (...args) {
    const now = Date.now()
    if (now - last >= delay) {
      last = now
      fn.apply(this, args)
    }
  }
}
```

## 10. 继承（ES5 vs ES6）

**ES6 `class extends`**：本质是原型链 + `super`。`super()` 调用父类构造器。

**追问：`class` 是语法糖吗？** 大部分是，但有差异：class 有 `constructor` 必须 `new` 调用（不能当普通函数）、方法不可枚举、有 `super` 关键字、内部严格模式。

## 11. ES6+ 新特性

高频问，按「能背出 8-10 个 + 每个一句话」准备：

1. **let/const**：块级作用域，无变量提升（有暂时性死区 TDZ），const 不可重新赋值（引用类型内容可变）。
2. **箭头函数**：无自己的 this、arguments、prototype，不能 new。
3. **解构赋值**：数组/对象解构，可设默认值。
4. **模板字符串**：反引号 + `${}` 插值。
5. **展开/剩余运算符**：`...` 展开数组对象、收集剩余参数。
6. **默认参数**：函数参数默认值。
7. **Promise**：解决回调地狱。
8. **Symbol**：唯一值。
9. **Proxy/Reflect**：拦截对象操作。
10. **Generator**：`function*` + yield 可暂停。
11. **class**：面向对象语法糖。
12. **模块化**：ESM import/export。
13. **Map/Set/WeakMap/WeakSet**：新集合类型。
14. **可选链 `?.` / 空值合并 `??`**：安全访问、默认值。

## 12. 数组方法

| 方法 | 返回值 | 是否改原数组 |
|---|---|---|
| `map` | 新数组 | 否 |
| `filter` | 过滤后新数组 | 否 |
| `reduce` | 累加结果 | 否 |
| `forEach` | undefined | 否 |
| `some`/`every` | boolean | 否 |
| `find`/`findIndex` | 元素/下标 | 否 |
| `push`/`pop`/`shift`/`unshift` | 长度/元素 | **是** |
| `splice` | 删除元素数组 | **是** |
| `slice` | 新数组 | 否 |
| `concat` | 新数组 | 否 |

**追问：reduce 怎么用？** 累加器模式，`arr.reduce((acc, cur) => acc + cur, 0)`。可用于求和、扁平化、分组、手写 map 等。

```js
// 用 reduce 手写 map / 数组扁平化
const map = (arr, fn) => arr.reduce((acc, cur) => [...acc, fn(cur)], [])
const flat = arr => arr.reduce((acc, cur) => acc.concat(Array.isArray(cur) ? flat(cur) : cur), [])
```

## 13. 垃圾回收机制

- **引用计数**：计数为 0 回收。**缺点**：循环引用永远不为 0 → 内存泄漏。
- **标记清除（主流）**：从根对象（全局、活动调用栈）出发，标记所有可达对象，未标记的回收。解决循环引用。
- **V8 分代回收**：新生代（Scavenge 复制算法，存活对象少）→ 晋升老生代（标记清除 + 标记整理，碎片化处理）。

**常见内存泄漏**：全局变量、未清理的定时器/事件监听、闭包、DOM 引用未释放。

## 14. Symbol / Set / Map / WeakMap

- **Symbol**：独一无二的值。用途：对象私有属性、`Symbol.iterator`、`Symbol.toStringTag`、防止属性名冲突。
- **Set**：唯一值集合，`add/delete/has/size`，可去重、可遍历。
- **Map**：键值对，键可以是任意类型、有序、可遍历。对比对象：键不会强制转字符串。
- **WeakMap**：**键必须是对象、弱引用、不可遍历、没有 size**。用途：存 DOM 元数据、私有属性（防内存泄漏）——深拷贝里用 WeakMap 就是这原因。

## 15. Iterator / Generator / async

- **Iterator**：`Symbol.iterator` 返回一个带 `next()` 的对象，`{value, done}`。`for...of` 依赖它。
- **Generator**：`function*` + `yield`，可暂停/恢复，返回 Iterator。用于异步流程控制、惰性求值。
- **async/await 本质**：Generator + Promise 的语法糖（`await` = 自动执行 generator 的 next）。

## 16. Proxy 与 Reflect

- **Proxy**：拦截对象操作（get/set/has/deleteProperty/ownKeys 等 13 个陷阱），返回新代理对象。
- **Reflect**：操作对象的默认行为，方法与 Proxy 陷阱一一对应，让默认操作统一、返回值更合理。
- **Vue3 响应式**：用 Proxy 代理整个对象，解决 Vue2 `Object.defineProperty` 无法检测新增/删除属性、数组索引的问题。

## 17. 函数式编程

- **纯函数**：同输入同输出、无副作用（不修改外部状态）。
- **柯里化**：把多参函数转成单参函数链。`f(a,b,c) → f(a)(b)(c)`。
- **组合 compose**：`compose(f, g)(x) = f(g(x))`，从右到左组合。

```js
const curry = fn => (...args) =>
  args.length >= fn.length ? fn(...args) : (...rest) => curry(fn)(...args, ...rest)
```

## 18. 手写题高频清单

> 面试手写题大概率从这出，全部要能默写。

1. **手写 `new`**：创建空对象 → 原型指向构造器 prototype → 执行构造器绑定 this → 返回对象（构造器返回对象则用返回值）。
2. **手写 `call/apply/bind`**：把 fn 临时挂到 context 上调用再删除。
3. **手写 `instanceof`**：沿 `__proto__` 链找 `prototype`。
4. **手写 `Promise` / `Promise.all` / `allSettled`**（见下）。
5. **手写深拷贝 / 防抖 / 节流 / 柯里化**（见上）。
6. **手写发布订阅 EventEmitter**（见下）。
7. **手写并发请求限制**（见下）。

```js
// 手写 Promise.all
Promise.myAll = function (promises) {
  return new Promise((resolve, reject) => {
    const result = []
    let count = 0
    promises.forEach((p, i) => {
      Promise.resolve(p).then(v => {
        result[i] = v
        if (++count === promises.length) resolve(result)
      }, reject)
    })
  })
}

// 手写发布订阅（EventEmitter）—— 面试记录里的薄弱点，重点掌握
class EventEmitter {
  constructor() { this.events = {} }
  on(type, fn) {
    (this.events[type] ||= []).push(fn)
    return this
  }
  once(type, fn) {
    const wrap = (...args) => { fn.apply(this, args); this.off(type, wrap) }
    return this.on(type, wrap)
  }
  off(type, fn) {
    if (!this.events[type]) return
    this.events[type] = fn
      ? this.events[type].filter(f => f !== fn)
      : []
  }
  emit(type, ...args) {
    ;(this.events[type] || []).slice().forEach(fn => fn.apply(this, args))
  }
}

// 手写并发请求限制（每次最多 limit 个并发）
function limitConcurrency(urls, limit) {
  const results = []
  let index = 0, running = 0
  return new Promise((resolve, reject) => {
    function next() {
      if (index === urls.length && running === 0) return resolve(results)
      while (running < limit && index < urls.length) {
        const i = index++
        running++
        fetch(urls[i])
          .then(r => results[i] = r)
          .catch(reject)
          .finally(() => { running--; next() })
      }
    }
    next()
  })
}
```

# 二、HTML 核心

## 1. DOCTYPE 与渲染模式

**DOCTYPE** 声明文档类型，告诉浏览器用**标准模式**渲染。不写或写错会触发**怪异模式（Quirks Mode）**，导致盒模型、布局解析不一致。

**HTML5 只需** `<!DOCTYPE html>`。

**追问：标准模式和怪异模式区别？** 怪异模式兼容老页面，盒模型按 IE5 处理（width 含 padding/border）、行内元素高度解析不同等。所以必须写 DOCTYPE。

## 2. 语义化标签

**常用**：`header`、`nav`、`main`、`article`、`section`、`aside`、`footer`、`figure`、`time`。

**好处**：① 结构清晰、可维护性好；② SEO（搜索引擎理解内容结构）；③ 无障碍（屏幕阅读器）；④ 比 `<div>` 有意义。

## 3. meta 标签

```html
<meta charset="UTF-8">                       <!-- 字符编码 -->
<meta name="viewport" content="width=device-width, initial-scale=1"> <!-- 移动端视口 -->
<meta name="description" content="页面描述">  <!-- SEO -->
<meta name="keywords" content="关键词">
<meta property="og:title" content="...">     <!-- 分享卡片 -->
```

**追问：viewport 干什么的？** 让移动端页面宽度等于设备宽度、初始缩放 1:1，避免手机把桌面布局缩小显示。

## 4. script 的 defer / async

- **普通 script**：遇到就下载并执行，**阻塞** HTML 解析。
- **`async`**：异步下载，下载完**立即执行**（不管 HTML 解析完没，执行顺序不确定）。
- **`defer`**：异步下载，等 HTML **解析完成后、DOMContentLoaded 前按顺序执行**。

**选型**：无依赖的第三方脚本用 async；有依赖关系、需要 DOM 的脚本用 defer。

## 5. 本地存储对比

| 存储 | 容量 | 生命周期 | 是否随请求发送 | 作用域 |
|---|---|---|---|---|
| **cookie** | ~4KB | 可设过期时间 | **每次请求自动携带** | 同源、可跨路径 |
| **localStorage** | ~5MB | 永久（手动删） | 否 | 同源 |
| **sessionStorage** | ~5MB | 标签页关闭即清 | 否 | 同源 + 单标签页 |

**追问：cookie 有哪些属性？** `HttpOnly`（JS 读不到，防 XSS）、`Secure`（仅 HTTPS）、`SameSite`（防 CSRF）、`Max-Age/Expires`、`Domain/Path`。

## 6. canvas vs svg

- **canvas**：位图，JS 绘制，像素级操作，缩放会失真，适合游戏/图表/图像处理。
- **svg**：矢量图，XML 描述，缩放不失真，DOM 元素可绑定事件、可被 CSS 控制，适合图标/简单图形。

## 7. 事件机制与委托

**三阶段**：捕获（capture）→ 目标（target）→ 冒泡（bubble）。`addEventListener(type, fn, useCapture)`，第三参数 true 走捕获。

**事件委托**：把子元素的事件监听挂在父元素上，利用冒泡，通过 `e.target` 判断实际触发元素。**优点**：动态增删元素无需重新绑定、减少监听器数量。

```js
ul.addEventListener('click', e => {
  if (e.target.tagName === 'LI') console.log(e.target.textContent)
})
```

**追问：怎么阻止冒泡/默认行为？** `e.stopPropagation()` 阻止冒泡；`e.preventDefault()` 阻止默认行为；`e.stopImmediatePropagation()` 阻止同元素上其他监听器。

## 8. SEO 与无障碍

- **SEO**：语义化标签、`title`/`description`、图片 `alt`、链接用 `<a>` 不用 JS 跳转、SSR/预渲染（SPA 对 SEO 不友好）。
- **无障碍（a11y）**：语义化、`alt` 文本、`aria-*` 属性、`role`、键盘可操作、对比度、焦点管理。

# 三、CSS 核心

## 1. 盒模型

- **content-box（默认）**：`width` 只算内容区，实际宽 = width + padding + border。
- **border-box**：`width` = content + padding + border，**更符合直觉**，常用 `* { box-sizing: border-box }`。

## 2. BFC（块级格式化上下文）

**是什么**：一个独立的渲染区域，内部布局不影响外部。

**解决什么**：
1. **margin 塌陷**（父子/兄弟 margin 重叠）
2. **清除浮动**（父元素高度塌陷）
3. **阻止浮动元素覆盖**（两栏布局）

**触发条件**：`overflow: hidden/auto/scroll`（非 visible）、`float` 非 none、`position: absolute/fixed`、`display: inline-block/flex/grid`、根元素 `<html>`。

## 3. 选择器优先级

**优先级（从高到低）**：`!important` > 内联样式 > ID > class/属性/伪类 > 元素/伪元素。

权重 `(a, b, c, d)`：内联 `a`，ID 数 `b`，class/伪类数 `c`，元素/伪元素数 `d`。逐位比较，a 最高。

**追问：`!important` 为什么尽量不用？** 破坏优先级规则，后续覆盖困难，只能再用 !important 覆盖，代码越来越难维护。

## 4. 居中方案

| 场景 | 方案 |
|---|---|
| 水平居中（行内） | `text-align: center` |
| 水平居中（块） | `margin: 0 auto` |
| 水平居中（flex） | `display:flex; justify-content:center` |
| 垂直居中（行内） | `line-height` = 高度 |
| 垂直水平居中（flex） | `display:flex; align-items:center; justify-content:center` |
| 垂直水平居中（grid） | `display:grid; place-items:center` |
| 绝对定位居中 | `position:absolute; top/left:50%; transform:translate(-50%,-50%)` |

## 5. flex 与 grid

- **flex**：一维布局。`justify-content`（主轴）、`align-items`（交叉轴）、`flex: 1`（= flex-grow:1 flex-shrink:1 flex-basis:0%）。
- **grid**：二维布局。`grid-template-columns`、`grid-template-rows`、`gap`、`place-items`。

**选型**：一维（一行/一列）用 flex，二维网格用 grid。

## 6. position 定位

- **static**：默认，文档流。
- **relative**：相对自身偏移，不脱离文档流。
- **absolute**：相对最近的**非 static 祖先**（定位上下文）偏移，脱离文档流。
- **fixed**：相对视口，脱离文档流（注意移动端软键盘、transform 祖先会影响）。
- **sticky**：relative + fixed 结合，滚动到阈值后固定。

**追问：包含块（containing block）？** 决定 absolute 元素定位参照的元素。absolute 的包含块是最近的非 static 祖先；fixed 的包含块是视口（但祖先有 transform/filter 时变成该祖先）。

## 7. 层叠上下文

**是什么**：决定元素 z 轴叠放顺序的独立层级。z-index 只在同一层叠上下文内比较。

**触发条件**：`position + z-index`、`opacity < 1`、`transform`、`filter`、`will-change`、`flex` 子项带 z-index 等。

**坑**：父元素创建了层叠上下文后，子元素 z-index 再大也无法盖过父元素同级的兄弟层。

## 8. 单位 rem / em / vw

- **rem**：相对**根元素**（html）字体大小。默认 16px，`1rem = 16px`。
- **em**：相对**父元素**字体大小（会级联放大）。
- **vw/vh**：视口宽/高的 1%。
- **移动端适配**：rem 方案（html font-size 按屏宽动态设置）+ 媒体查询 + 百分比。

## 9. 响应式布局

- **媒体查询**：`@media (max-width: 768px) {}`。
- **rem + flexible**：动态设置 html font-size。
- **百分比/流式**：宽度用百分比。
- **flex/grid**：弹性布局自适应。
- **移动优先**：先写移动端，再 `min-width` 增强。

## 10. 伪类 vs 伪元素

- **伪类 `:`**：描述元素**状态**，`:hover`、`:active`、`:nth-child`、`:focus`、`:first-child`。
- **伪元素 `::`**：创建**不存在的元素**，`::before`、`::after`、`::placeholder`。不占 DOM，可用于装饰、清除浮动。

## 11. CSS 动画

- **transition**：需要**触发**（hover/类切换），从 A 到 B 的过渡，只能定义起止状态。
- **animation**：`@keyframes` 定义关键帧，可自动播放、循环、多状态。

**性能**：优先用 `transform`/`opacity`（走 GPU 合成层，不触发回流），避免动画 `left/top/width`（触发回流）。

## 12. 移动端 1px 问题

**原因**：Retina 屏 DPR=2/3，CSS 的 1px 渲染成 2-3 个物理像素，看起来粗。

**解决**：
1. `transform: scale(0.5)`（配合伪元素，最常用）
2. 用 `viewport` 的 `initial-scale` 按 DPR 缩放
3. 边框用 `border-image` 或 `box-shadow`
4. 直接设计稿按 1 物理像素用 0.5px（兼容性差）

# 四、移动端兼容性

## 1. 300ms 点击延迟

**原因**：早期 iOS Safari 为区分「单击」和「双击缩放」，click 事件延迟 300ms 等待第二次点击。

**解决**：
1. `<meta name="viewport" content="width=device-width">` 声明视口（禁用双击缩放）
2. 用 `touch` 事件或 fastclick 库
3. 现代浏览器已基本解决，主要兼容老 WebView

## 2. 100vh 与地址栏

**问题**：iOS Safari 地址栏/工具栏会占用视口，`100vh` 比实际可视高度大，底部内容被裁或被遮挡。

**解决**：
1. 用 `100dvh`（动态视口单位，随地址栏变化）
2. JS 动态计算 `window.innerHeight` 设置高度
3. `height: 100%` 配合容器

## 3. 软键盘问题

**问题**：
- Android：键盘弹出触发 resize，`position: fixed` 元素被顶起错位
- iOS：键盘弹出**不触发 resize**，输入框被键盘遮挡
- 键盘弹出导致 flex 布局被压缩

**解决**：
- iOS 输入框遮挡：监听 `focusin`，`scrollIntoView` 手动滚动到可视区
- fixed 错位：键盘弹出时改成 absolute 或隐藏 fixed 元素
- 用 `visualViewport` API 监听可视视口变化

## 4. 安全区（刘海屏）

**问题**：iPhone X 起有刘海和底部 Home 指示条，内容可能被遮挡。

```html
<meta name="viewport" content="width=device-width, viewport-fit=cover">
```
```css
.safe {
  padding-bottom: constant(safe-area-inset-bottom); /* 旧 iOS */
  padding-bottom: env(safe-area-inset-bottom);
}
```

## 5. iOS 日期解析

**问题**：`new Date('2020-01-01')` 在 iOS Safari 返回 Invalid Date（iOS 不认 `-` 分隔）。

**解决**：统一用 `/` 分隔或时间戳：`new Date('2020/01/01')`，或 `new Date('2020-01-01'.replace(/-/g, '/'))`。

## 6. 滚动穿透

**问题**：弹窗/浮层内滚动时，背景页面跟着滚。

**解决**：
1. 弹窗打开时给 body 加 `overflow: hidden` 或 `position: fixed` 锁定
2. CSS `overscroll-behavior: contain`
3. 阻止背景的 touchmove

**惯性滚动**：iOS 滚动容器卡顿/无惯性，加 `-webkit-overflow-scrolling: touch`。

## 7. 字体缩放

**问题**：
- Android：系统「字体大小」设置影响 WebView 内字体
- iOS：输入框 `font-size < 16px` 时，聚焦会触发页面自动放大

**解决**：
- iOS 输入框字体设为 ≥16px（或用 `transform: scale` 缩小视觉字号）
- Android 字体用固定 px，或 WebView 配置禁用字体缩放

## 8. 点透问题

**问题**：touch 事件后 300ms 触发的 click 会「点透」到下层元素（如关闭 mask 后点击穿透到下面的按钮）。

**解决**：触摸事件里 `e.preventDefault()`、用 fastclick、mask 延迟销毁、改用 touch 事件。

## 9. 音视频自动播放

**问题**：iOS/Android 都禁止无用户交互时自动播放音视频。

**解决**：首次播放需用户手势触发，或视频加 `muted` 属性允许自动播放（静音自动播放）。

## 10. 图片模糊（DPR）

**问题**：Retina 屏 DPR=2/3，1x 图片在高清屏显示模糊。

**解决**：`<img srcset>` 提供 2x/3x 图，或背景图用媒体查询按 DPR 切换。

# 五、React 核心

## 1. Fiber 架构

**为什么需要 Fiber**：React 15 的 Stack Reconciler 递归同步执行，深组件树 diff 会长时间占用主线程，导致掉帧、卡顿。

**Fiber 是什么**：React 16 重构的协调引擎，把渲染任务拆成可中断的小单元（Fiber 节点），配合优先级调度，实现**可中断、可恢复的异步渲染**。

**双缓冲**：`current`（屏幕上）和 `workInProgress`（内存中构建）两棵 Fiber 树交替，commit 后翻转指针，避免渲染一半被看见。

**两阶段**：
- **Render 阶段**（可中断）：构建 Fiber 树、diff、标记副作用。
- **Commit 阶段**（不可中断）：一次性更新 DOM，触发生命周期/useEffect。

**追问：怎么中断和恢复？** 通过 `requestIdleCallback`（或 Scheduler 包的 `MessageChannel` 模拟）在浏览器空闲时执行工作，有更高优先级任务（如用户输入）就中断，保存进度，之后恢复。

## 2. Diff 算法

**三个假设（让 O(n³) 降到 O(n)）**：
1. 只对**同级**元素比较，不跨层级。
2. 不同类型元素生成不同树（`div`→`span` 整体替换）。
3. 用 `key` 标识元素，判断增删移动。

**追问：为什么不能用 index 当 key？** 列表重排时 index 不变，React 误以为元素没变，导致错误复用 DOM、状态错乱（如输入框内容串位）。用稳定唯一 ID。

## 3. Hooks 原理

**useState 为什么不能放条件里**：React 靠**调用顺序**维护 Hook 链表（`Fiber.memoizedState` 单向链表）。每次渲染按同一顺序取 Hook，顺序变了状态就错位。

**useEffect vs useLayoutEffect**：
- `useEffect`：渲染提交后**异步**执行，不阻塞，用于请求/订阅。
- `useLayoutEffect`：DOM 更新后、浏览器绘制前**同步**执行，阻塞渲染，用于测 DOM、避免闪烁。

**useMemo vs useCallback**：
- `useMemo`：缓存**计算结果**。
- `useCallback`：缓存**函数引用**（配合 `React.memo` 才有意义，否则是负优化）。

**追问：滥用 memo 的坏处？** 每次渲染都要比较依赖、多一层开销，简单组件反而变慢；依赖写错还会导致「不更新」的 bug。

## 4. 闭包陷阱与解决

**经典问题**：`useEffect` 里读取 state，依赖数组没写全，读到旧值。

```js
const [count, setCount] = useState(0)
useEffect(() => {
  const timer = setInterval(() => console.log(count), 1000) // 永远打印 0
  return () => clearInterval(timer)
}, []) // count 被闭包捕获，不会更新
```

**解决**：① 依赖数组补上 `count`；② 用函数式更新 `setCount(c => c + 1)`；③ 用 `useRef` 存最新值；④ 用 `useReducer`。

**追问：函数式更新为什么能解决？** `setCount(c => c + 1)` 传入的是函数，React 会把最新的 state 传进去，不依赖闭包里的旧值。

## 5. React 18 / 19 新特性

**React 18**：
- `createRoot`（开启并发特性）。
- **自动批处理**（Automatic Batching）：同一事件里的多次 setState 自动合并，减少渲染。
- **并发特性**：`useTransition`（标记非紧急更新）、`useDeferredValue`（延迟更新）、`Suspense` 支持 SSR。
- 结论：`useTransition` 解决「输入框输入被大列表渲染卡住」——把列表更新标记为低优先级，让输入保持流畅。

**React 19**（面试高频，八爪鱼二面问过）：
- **React Compiler**：自动记忆化（auto-memoization），编译时自动插入 `useMemo`/`useCallback`，开发者不用手写 —— 解决 memo 手动维护的痛点。
- **Actions**：表单提交内置处理 pending 状态，`useActionState`、`useFormStatus`、`useOptimistic`（乐观更新）。
- **`use()` hook**：在组件里直接读取 Promise/Context，配合 Suspense。
- **Server Components 稳定**、ref 可作为 prop 直接传、`<form>` 增强。

**追问：React Compiler 原理？** 编译时静态分析组件，找出哪些计算/函数依赖了哪些值，自动缓存，依赖变化才重算。本质是把运行时 memo 判断前移到编译期。

## 6. 状态管理选型

- **Zustand**：极简 API、无 Provider、selector 精确渲染、<1KB、TS 友好。
- **Redux Toolkit**：成熟生态、中间件、时间旅行调试、适合大型复杂应用。
- **选择**：中后台/中小项目 Zustand 够用；需要严格状态流/团队规范用 Redux。

**追问：Zustand 怎么做到不 Provider 且精确渲染？** 基于发布订阅 + `useSyncExternalStore`，store 是模块级单例，组件通过 selector 订阅，只有 selector 返回值变化才重渲染。

# 六、计算机网络

## 1. OSI 七层 vs TCP/IP 四层

| OSI 七层 | TCP/IP 四层 | 常见协议 |
|---|---|---|
| 应用层 | 应用层 | HTTP、HTTPS、DNS、FTP、SMTP |
| 表示层 | 应用层 | — |
| 会话层 | 应用层 | — |
| 传输层 | 传输层 | TCP、UDP |
| 网络层 | 网络层 | IP、ICMP、ARP |
| 数据链路层 | 网络接口层 | 以太网、MAC |
| 物理层 | 网络接口层 | 光纤、网线 |

**记忆**：TCP/IP 把 OSI 上三层（应用/表示/会话）合并成应用层，下两层（数据链路/物理）合并成网络接口层。

## 2. TCP 三次握手 / 四次挥手

**三次握手（建立连接）**：
1. 客户端 → 服务端：`SYN`
2. 服务端 → 客户端：`SYN + ACK`
3. 客户端 → 服务端：`ACK`

**为什么三次不是两次？** 两次无法确认双方收发能力都正常，且可能因失效的连接请求导致服务端单方面建立连接、浪费资源。三次是最小次数能保证双方都确认。

**四次挥手（断开连接）**：
1. 客户端 → 服务端：`FIN`（我不发了）
2. 服务端 → 客户端：`ACK`（知道了）
3. 服务端 → 客户端：`FIN`（我也不发了）
4. 客户端 → 服务端：`ACK`

**为什么四次不是三次？** 全双工，双方独立关闭。服务端收到 FIN 后可能还有数据没发完，先 ACK 表示收到，发完再发 FIN，所以 ACK 和 FIN 分两步。

**追问：TIME_WAIT 为什么等 2MSL？** 确保最后一个 ACK 能被对方收到（丢了对方会重发 FIN），且让本次连接的报文在网络上消失，避免影响新连接。

## 3. TCP vs UDP

| | TCP | UDP |
|---|---|---|
| 连接 | 面向连接（握手） | 无连接 |
| 可靠性 | 可靠（确认/重传/序号） | 不可靠 |
| 速度 | 慢 | 快 |
| 首部 | 20 字节 | 8 字节 |
| 应用 | HTTP、文件传输 | 视频、游戏、DNS、直播 |

## 4. HTTPS 与 TLS 握手

**HTTPS = HTTP + TLS/SSL**。加密通信，防窃听、防篡改、防冒充。

**加密方案（混合）**：非对称加密（RSA/ECDHE）协商密钥 → 对称加密（AES）加密数据。因为非对称慢，对称快。

**TLS 握手（简化）**：
1. ClientHello（支持版本、加密套件、随机数）
2. ServerHello（选定套件）+ 证书 + 随机数
3. 客户端验证证书（CA 签名链），生成预主密钥，用证书公钥加密发送
4. 双方用三个随机数生成会话密钥，切换对称加密

**追问：为什么要有证书？** 防中间人攻击——证书由 CA 签名，客户端用 CA 公钥验证服务器身份，确保公钥确实是服务器的。

## 5. DNS 解析过程

1. 浏览器/系统缓存 → 本地 hosts → 本地 DNS 服务器（递归查询）
2. 本地 DNS 服务器向**根域名服务器** → 顶级域（.com）→ 权威服务器（迭代查询）
3. 得到 A 记录（IP），返回并缓存

**追问：DNS 优化？** `dns-prefetch`、CDN 就近解析、HTTPDNS（绕过运营商 DNS 防劫持）。

## 6. HTTP 版本演进

| 版本 | 关键特性 |
|---|---|
| HTTP/0.9 | 只有 GET、纯文本、无请求/响应头 |
| HTTP/1.0 | 请求头/响应头、状态码、多文件类型 |
| HTTP/1.1 | **keep-alive 长连接**、**管线化**、缓存增强（Cache-Control/ETag）、Range 断点续传 |
| HTTP/2 | **二进制分帧**、**多路复用**（解决队头阻塞）、头部压缩 HPACK、服务器推送 |
| HTTP/3 | 基于 **QUIC(UDP)**、0-RTT、连接迁移、彻底解决队头阻塞 |

**追问：HTTP/1.1 管线化 vs HTTP/2 多路复用？** 1.1 管线化仍按顺序响应（队头阻塞），且兼容性差基本没人用。2.0 通过二进制分帧 + stream id，响应可以乱序、并行，真正解决队头阻塞。

**追问：HTTP/3 为什么用 UDP？** 基于 QUIC，把 TCP 的可靠传输、TLS 加密下沉到 UDP 上的传输层，减少握手 RTT（0-RTT），且一个连接不因单个包丢失阻塞所有流（连接级无队头阻塞）。

## 7. Cookie / Session / Token / JWT

- **Cookie**：客户端存，4KB，每次请求携带。`HttpOnly`/`Secure`/`SameSite`。
- **Session**：服务端存，靠 sessionId（存 cookie）关联。有状态、服务端压力。
- **Token/JWT**：无状态、自包含（header.payload.signature），服务端不存，适合分布式/移动端。

**追问：JWT 怎么验证？** 客户端带 token，服务端用密钥验证签名、检查过期时间，无需查库。**缺点**：一旦签发无法主动失效（除非加黑名单）。

## 8. 状态码

| 状态码 | 含义 |
|---|---|
| 200 | OK |
| 201 | Created（创建成功） |
| 204 | No Content |
| 301 | 永久重定向 |
| 302 | 临时重定向 |
| 304 | Not Modified（缓存） |
| 400 | 请求错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 未找到 |
| 500 | 服务器内部错误 |
| 502 | 网关错误（上游挂了） |
| 503 | 服务不可用（过载/维护） |
| 504 | 网关超时 |

## 9. GET vs POST

| | GET | POST |
|---|---|---|
| 幂等性 | 幂等（多次结果一样） | 非幂等 |
| 缓存 | 可缓存 | 一般不缓存 |
| 参数位置 | URL（有长度限制） | 请求体 |
| 安全性 | 参数暴露在 URL/日志 | 相对好（但仍可被抓包） |

**追问：GET 有长度限制吗？** 浏览器和服务器对 URL 长度有限制（约 2KB-8KB），是环境限制不是协议规定。

## 10. RESTful

- **资源 + HTTP 动词**：GET 查、POST 增、PUT/PATCH 改、DELETE 删。
- **无状态**：每次请求独立，服务端不存客户端状态。
- **URL 用名词**：`/users/1` 不用 `/getUser`。

## 11. CDN

**是什么**：内容分发网络，把资源缓存到离用户最近的边缘节点，减少网络延迟。

**流程**：DNS 解析 → CNAME 到 CDN 调度域名 → GSLB（智能 DNS）按 IP/运营商/负载选最优边缘节点 → 边缘节点有缓存直接返回，没有就**回源**到源站再缓存。

**追问：缓存刷新/预热？** 预热是提前把资源分发到各节点；刷新是主动失效缓存、回源取新内容（大版本更新时用）。

# 七、浏览器与性能

## 1. 渲染机制

**从 URL 到页面**：
DNS 解析 → TCP 连接（+TLS）→ HTTP 请求 → 响应 → 解析 HTML 建 DOM → 解析 CSS 建 CSSOM → 合成 Render Tree → Layout（回流）→ Paint（重绘）→ Composite（合成）。

## 2. 回流 / 重绘 / 合成层

- **回流（Reflow）**：几何属性变化（宽高、位置、增删 DOM、字体、resize），重排布局，成本高。
- **重绘（Repaint）**：仅外观变化（颜色、阴影、背景），成本低。
- 回流必触发重绘，重绘不一定回流。

**合成层（Compositing）**：GPU 独立绘制的层，跳过 Layout/Paint。触发：`transform`、`opacity` 动画、`will-change`、`video`/`canvas`、`filter`。**坑**：层太多内存暴涨（层爆炸）。

**优化**：`transform` 代替 `left/top`、批量改样式（class）、`DocumentFragment`、`display:none` 后再操作、避免强制同步布局（循环里读 offsetTop）。

## 3. 浏览器缓存

**强缓存**（不发请求）：
- `Cache-Control: max-age=31536000`（HTTP/1.1，优先）
- `Expires: <日期>`（HTTP/1.0）

**协商缓存**（发请求，304）：
- `ETag` / `If-None-Match`（内容指纹，优先，精确）
- `Last-Modified` / `If-Modified-Since`（时间戳，秒级精度，有缺陷）

**追问：ETag 和 Last-Modified 为什么优先 ETag？** Last-Modified 秒级精度不够、文件内容没变但 mtime 变了会误判、某些服务器不准确。ETag 是内容哈希，更精确。

**完整流程**：请求 → 命中强缓存直接返回 → 未命中发请求带协商头 → 服务端判断 → 304 用缓存 / 200 返回新内容。

## 4. 跨域与解决方案

**为什么跨域**：浏览器同源策略（协议 + 域名 + 端口都相同），限制跨源读写。

**解决方案**：

| 方案 | 原理 | 适用 |
|---|---|---|
| **CORS** | 服务端加 `Access-Control-Allow-Origin` 等响应头 | 主流，最常用 |
| **JSONP** | `<script>` 标签不受同源限制，回调函数包裹数据 | 老项目、只支持 GET |
| **代理** | 前端 devServer proxy 转发，同源 | 开发环境 |
| **postMessage** | 跨 window 通信 | iframe 父子 |
| **WebSocket** | 不受同源限制 | 双向实时通信 |
| **Nginx 反向代理** | 转发到同源 | 生产 |

**追问：CORS 的简单请求和预检请求？** 简单请求（GET/HEAD/POST + 限定 Content-Type）直接发；非简单请求（自定义头、PUT/DELETE、`application/json`）先发 **OPTIONS 预检**，服务端确认允许后才发真实请求。

**追问：Cookie 跨域要带什么？** 服务端 `Access-Control-Allow-Credentials: true`，前端 `withCredentials: true`（fetch 是 `credentials: 'include'`），且 `Allow-Origin` 不能用 `*`。

## 5. 安全（XSS / CSRF）

**XSS（跨站脚本）**：注入恶意脚本执行。
- **存储型**：恶意脚本存进数据库（评论区），其他用户访问时执行。
- **反射型**：URL 参数注入，服务端反射回页面。
- **DOM 型**：前端 JS 拼接用户输入执行。
- **防御**：输入校验、输出转义、`CSP`、`HttpOnly` Cookie、不用 `innerHTML` 拼用户输入（用 textContent / 框架的自动转义）。

**CSRF（跨站请求伪造）**：诱导用户浏览器携带 Cookie 发恶意请求。
- **防御**：`SameSite=Lax/Strict`、验证 `Referer`/`Origin`、CSRF Token、关键操作二次验证。

**追问：SameSite 三种值？** `Strict`（完全禁止跨站携带）、`Lax`（仅顶级导航 GET 携带，默认）、`None`（完全允许，需 `Secure`）。

## 6. 性能指标与优化

**核心指标**：FCP（首次内容绘制）、LCP（最大内容绘制，SEO 核心）、TTI（可交互）、TBT（总阻塞时长）、CLS（布局偏移）、INP（交互响应，替代 FID）。

**优化思路**：
- **资源**：代码分割 + 懒加载、CDN、Gzip/Brotli、图片 WebP + 懒加载 + 响应式。
- **渲染**：关键 CSS 内联、虚拟列表、`content-visibility`、避免强制同步布局。
- **网络**：预请求（prefetch/preconnect）、并行加载、HTTP/2。
- **框架**：`React.memo` + `useMemo`/`useCallback`（适量）、`Suspense`。

# 八、工程化

## 1. 构建工具

**Webpack vs Vite**：
- **Webpack**：Bundle 模式，先全量打包再启动，大项目冷启动慢；生态成熟。
- **Vite**：开发时 No-Bundle，用浏览器原生 ESM 按需编译，启动快；生产用 Rollup 打包。
- **Vite 快的原因**：依赖预构建用 esbuild（Go，快 10-100 倍）；源码按需编译，只编译浏览器请求的模块。

**追问：Vite 为什么生产用 Rollup？** esbuild 虽快但生产级代码分割、Tree shaking、产物优化能力不如 Rollup 成熟稳定。

## 2. 模块化

- **CommonJS**：`require`/`module.exports`，同步加载，Node 默认。
- **ESM**：`import`/`export`，静态分析（可 Tree shaking）、异步加载，浏览器 + 现代 Node。

**区别**：CJS 是值的拷贝，ESM 是值的引用（live binding）；CJS 运行时加载，ESM 编译时确定依赖；CJS 同步，ESM 异步；ESM 支持 Tree shaking，CJS 难。

## 3. Tree Shaking

**原理**：基于 ESM 的静态结构分析，编译时确定哪些导出被使用，摇掉未引用的代码。

**生效条件**：ESM（不是 CJS）、`sideEffects: false` 标记、不能动态导入、生产模式。

**追问：为什么 CJS 不能 tree shaking？** `require` 是运行时动态的，无法静态分析依赖关系，打包器不知道哪些代码用不到。

## 4. 代码分割（Code Splitting）

- **入口分割**：多入口。
- **动态导入**：`import()` → `React.lazy` + `Suspense` 路由懒加载。
- **提取公共**：`SplitChunksPlugin` 抽 vendor + 公共模块 + 第三方库单独 chunk。

**追问：为什么要抽 vendor？** 第三方库变更少，单独 chunk 可长期缓存；业务代码变更不影响 vendor 缓存命中。
