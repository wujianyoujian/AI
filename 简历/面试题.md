### 高级题

**Q6. [来自简历] 你在五福项目中深度使用了 Zustand + FSM，请问在 TypeScript 中如何对有限状态机的状态流转做严格类型约束，防止非法状态跳转？**
> 考察意图：TS 高级类型在业务模型中的实际应用

**参考答案要点：**
- 用 `type State = 'idle' | 'detecting' | 'gaming' | 'pairing' | 'rewarding' | 'error'` 定义联合类型
- 用映射类型 `Record<State, Partial<Record<State, () => void>>>` 定义合法转换表
- 利用 `never` 类型做穷举检查（exhaustive check）
- 在状态机 transition 函数入参处约束，编译期就能发现非法调用
- 结合 Zustand 的 `immer` 中间件保证状态不可变

**Q7. TypeScript 的协变（Covariance）与逆变（Contravariance）是什么？函数参数为什么是逆变的？**
> 考察意图：TS 类型系统高级特性，是否有深度理解

**参考答案要点：**
- 协变：子类型可赋值给父类型（返回值位置）
- 逆变：父类型可赋值给子类型（函数参数位置）
- 函数参数逆变保证类型安全（Liskov 替换原则）
- `strictFunctionTypes` 开关的影响
- 方法声明 vs 函数属性在协逆变上的差异

**Q8. 实现一个 `DeepReadonly<T>` 工具类型，递归地将所有属性设为只读。**
> 考察意图：TS 高级泛型、条件类型、递归类型的掌握

**参考答案要点：**
- 用 `{readonly [K in keyof T]: DeepReadonly<T[K]>}` 递归展开
- 处理 `T extends object` 的边界条件
- 处理数组类型的特殊情况
- 处理函数类型不递归的情况
- TS 4.1+ 递归类型的限制与绕过方式

**Q9. 说说 JS 内存泄漏的常见场景，在 React 应用中如何排查和解决？**
> 考察意图：内存管理与工程实践

**参考答案要点：**
- 闭包引用、事件监听未移除、定时器未清理
- React 中 useEffect cleanup 缺失导致的订阅泄漏
- WeakMap/WeakRef 的使用场景
- Chrome DevTools Memory 面板 Heap Snapshot 对比分析
- 结合候选人的 SSE 流式处理场景追问

**Q10. Promise.all、Promise.race、Promise.allSettled、Promise.any 的区别？如何实现并发控制（最多同时 N 个请求）？**
> 考察意图：异步编程高级应用，工程实践能力

**参考答案要点：**
- 四者语义差异（全成功/最快/全完成/任一成功）

### 高级题

**Q6. [来自简历] 你基于 Zustand 设计了 NFC 游戏的有限状态机，请画出状态流转图，并说明为什么选择 Zustand 而不是 XState 或 Redux？**

- XState 的优势（可视化、严格状态机）及引入成本

**参考答案要点：**
- 并发渲染：可中断的渲染，优先级调度
- Suspense：声明式的异步等待，与 lazy/数据获取结合
- useTransition：将状态更新标记为低优先级，保持 UI 响应
- useDeferredValue：对高频值降频处理
- 结合大规模节点画布场景的实际应用

**Q8. [来自简历] 在 AntV X6 画布中，你如何解决"大规模节点 React 组件嵌入 Canvas 渲染性能问题"？React 与 Canvas 的生命周期如何协调？**
> 考察意图：复杂渲染场景下 React 与 Canvas 的融合实践

**参考答案要点：**
- X6 的 React Shape 渲染原理：Portal 渲染到 foreignObject
- 虚拟化：只渲染视口内节点（类似虚拟列表）
- 节点复用：离屏节点 unmount vs 隐藏的策略选择
- React 批量更新（batching）与 X6 事件的协调
- 性能瓶颈定位：React DevTools Profiler + X6 内置 Profiler

**Q9. 描述 React Context 的性能问题及解决方案，什么场景下应该避免使用 Context？**
> 考察意图：Context 深度理解，架构决策能力

**参考答案要点：**
- Context value 变化导致所有消费者重渲染
- 解决方案：拆分 Context、useMemo 稳定 value、配合 memo
- 用 Zustand/Jotai 替代 Context 做全局状态
- Context 适合低频更新的配置项（Theme、i18n、Auth）
- 大型应用中 Context 的合理分层

**Q10. React 的合成事件系统是什么？为什么要用事件委托？React 17 后有什么变化？**
> 考察意图：React 事件系统深度

**参考答案要点：**
- SyntheticEvent：跨浏览器统一封装
- React 16：事件委托在 document 层
- React 17：事件委托移到 root container（解决微前端冲突）
- 与原生事件混用时的执行顺序问题
- stopPropagation 在合成事件与原生事件间的行为差异

> 考察意图：发布安全基础

**Q3. 什么是前端降级方案？如何设计功能开关（Feature Flag）？**
> 考察意图：稳定性设计基础

### 高级题

**Q4. [来自简历] 你主导了 2 次故障处置，请选择一次描述：故障现象是什么，如何快速定位根因，止血方案是什么，复盘后做了哪些改进？**
> 考察意图：故障处理真实经验，应急响应能力

**参考答案要点：**
- 故障现象的精确描述（影响用户数、影响功能）
- 定位过程：监控发现 → 日志排查 → 根因确认的时间线
- 止血方案：是回滚还是热修复，决策依据是什么
- 复盘：根因是代码缺陷/配置错误/上下游变更
- 改进 Action 的具体落地（不能停留在"加监控"这种泛化回答）

**Q5. [来自简历] 你将核心链路稳定性保持在 95%，请说明这个指标是如何定义和监测的？影响稳定性的主要因素有哪些，你是如何系统性地提升的？**
> 考察意图：稳定性指标体系与系统化提升能力

**参考答案要点：**
- 稳定性定义：核心链路（如支付流程）的成功率 = 成功请求 / 总请求
- 监测：关键埋点 + 服务端错误率 + 前端异常率的综合统计
- 影响因素：网络抖动、设备兼容性、JSBridge 调用失败、后端超时
- 系统性提升：预防（兼容性测试）+ 检测（实时监控）+ 恢复（降级兜底）
- 95% 到更高的卡点分析：剩余 5% 的主要失败原因是什么

**Q6. 如何设计一个前端错误监控系统，从错误采集到告警到修复的完整闭环？如何减少误报和漏报？**
> 考察意图：监控体系架构设计

**参考答案要点：**
- 采集：JS 运行时错误、Promise 未捕获、资源加载失败、接口错误
- 错误指纹：相同错误去重，按 message+stack hash 聚合
- 上下文信息：userAgent、网络状态、用户操作录像（rrweb）
- 告警策略：错误率突增（环比）+ 新错误（首次出现）双维度
- 减少误报：过滤已知第三方 script 错误、采样率控制
- 修复闭环：错误 → 工单 → 发版 → 验证的自动化链路

## 追问策略

当候选人给出模糊或套路化回答时，使用以下追问句式深入挖掘：

1. **量化追问**："你说'性能提升了很多'，具体的数字是多少？是怎么测量的？优化前后各是什么？"

2. **细节追问**："你说'用了虚拟列表'，具体是用了哪个库，还是自己实现的？实现的核心逻辑是什么？"

3. **决策追问**："为什么选择方案 A 而不是方案 B？当时有哪些备选方案，你们是如何做出最终决策的？"

4. **边界追问**："这个方案在哪些情况下会失效或有问题？你们有没有遇到过 Edge Case？"

5. **角色追问**："这个项目/优化是你独立完成的，还是团队合作？你具体负责了哪部分？"

6. **失败追问**："这个方案有没有遇到过问题或者失败过？你是怎么发现问题并调整的？"

7. **深度追问**："你提到用了 X 技术，能解释一下它的底层原理吗？如果让你从零实现一个简化版，你会怎么做？"

8. **扩展追问**："如果需求规模扩大 10 倍，现在这个方案还能用吗？你会如何改进？"
